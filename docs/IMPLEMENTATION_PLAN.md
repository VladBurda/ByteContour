# Implementation plan

Windows 10/11 is the primary release target. Use temporary fixture trees for filesystem tests. Record OS, Python version, storage hardware, fixture dimensions and commands alongside performance measurements. Each phase adds tests for its contracts and runs the full quality suite.

| Phase | Implementation sequence | Acceptance criteria |
| --- | --- | --- |
| **1 · Foundation** | Set up the uv package, diagnostics, then Qt theme, window and navigation. Add tests, CI, architecture and progress tracking. | A locked install starts the application. All eight destinations work by sidebar and keyboard, and the sidebar preference survives window recreation. JSON diagnostics contain timestamp, level, logger and message. Ruff lint and format, strict mypy and pytest pass locally. GitHub Actions is configured for Windows and Ubuntu with Python 3.12 and 3.13. |
| **2 · Scanner and persistence** | Define scan state and file identity, add migrations and repositories, implement traversal and incremental snapshots, then wire worker controls, progress and history. | Isolated fixtures verify exact file totals and correct skipping of links, denied or vanished entries, plus cancellation, pause/resume, interrupted writes and incremental add/change/remove detection. Measure throughput, insertion performance, and peak memory at 100k and 1M entries. On the documented local SSD fixture, target a Qt timer gap below 250 ms during a 100k-file scan and bound pending entries independently of total files. |
| **3 · Explorer and analytics** | Implement indexed page/aggregate queries, lazy tree and explorer models, volume capacity, filters, then chart drill-down and treemap. | A known tree yields exact totals and extension groups. Search, size/date/extension filtering, sorting and treemap selection agree with the inventory. A million-row fixture loads at most 500 entries per page. Measure main-thread timer gaps while browsing and target under 250 ms. |
| **4 · Duplicates** | Stream size groups, implement partial and full hashing and invalidation, persist groups, then add the preview and keeper selection UI. | Fixtures cover same-size mismatches, sample collisions, stale hashes, hard links and files changing during reads. Chunk memory remains bounded with large files. Verify keeper validation and byte comparison, and measure cold and warm duplicate runs including bytes read. |
| **5 · Safe cleanup** | Implement configurable candidate rules, validation and immutable previews, add native recycle and item audit, then integrate confirmation and recovery guidance. | Tests reject out-of-scope paths, protected folders, junctions, changed files, nonempty directories and removal of the final verified copy. An unsupported recycle operation and a locked file leave the source intact and record failure. Verify actual recycle behavior on disposable files on Windows. Every approved item receives an audit record. |
| **6 · Monitoring** | Add watchdog adapter, debounced ingest, bounded event queue, root settings and reconciliation. Add snapshots, growth chart and threshold notification. | Integration tests observe create, modify, move and delete events. Injected queue overflow marks the root stale and reconciliation restores totals that match a scan. Threshold notifications are deduplicated within the configured interval. Stop releases the observer and worker resources. |
| **7 · Recommendations** | Build the rule protocol and query context, add age/size, growth, duplicate, installer and temporary-file rules, then surface explanations and persist dismissals. | Deterministic fixtures verify each rule boundary, evidence explanation, risk, savings when defensible and dismissal across restart. Recommendations cannot dispatch filesystem changes. A separate test rule plugs in through the same protocol. |
| **8 · Release** | Measure and tune the representative benchmarks, finish edge-case coverage, add icons, package with PyInstaller, document and prepare release artifacts. | Document throughput, duplicate speed, insert rate, peak memory and UI responsiveness with reproducible commands. Smoke-test the Windows package on a clean machine without Python. Confirm critical workflows with temporary fixtures, capture screenshots, publish installation instructions and build release assets in CI. |

Phase 7 implements explainable recommendations and persistent dismissals. Phase 8 covers profiling, packaging, and release preparation.
